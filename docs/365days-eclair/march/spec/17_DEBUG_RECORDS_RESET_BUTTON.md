# 【今回の明示追加】失敗の記録に仮デバッグボタンを配置

## 用途
開発中に1周目の見せかけED → 真BAD017 → 2周目TRUEの切替を何度もテストするため、**1周目のエンディング到達フラグ `sf.true_bad_seen` のみfalseへリセット**する。一般ユーザー向けの恒久機能ではない。

## 位置と外観
- 既存の **「失敗の記録」** 画面内（ノートUI）。左ページの索引や右ページの記録詳細を塞がない**ページ下部／右下余白**などに、**小さめで明確にデバッグと分かる**ボタンを仮設置。
- ボタン文言例：`DEBUG｜1周目EDフラグ解除`。小さく状態を並記してよい：`true_bad_seen: ON/OFF`。
- 既存のUI色に馴染ませるが、通常のCORE/MINIタブ・ゲーム内アイテムには見せない。派手な新規画像制作は不要。HTML/CSSボタンで可。
- **現在の開発ビルドでは表示すること**。製品版に残してはいけないので、開発フラグ／機能トグル（例 `ENABLE_MARCH_ED_DEBUG_RESET`）で有効にする。フラグfalse時はUIもイベント処理も完全除去／無効にできる。

## 押下動作
1. ボタン押下→確認モーダル。
2. 内容例：`1周目ED到達フラグだけを解除します。失敗の記録・CG・セーブデータは削除しません。続けますか？` ボタンは**解除する／キャンセル**。
3. キャンセルは何も変更しない。
4. 実行：既存のシステム変数保存処理に従い**`sf.true_bad_seen = false` のみ永続化**する。フラグをメモリだけで書き換えて終わらない。
5. 記録画面のデバッグ状態表示を**OFF**へ更新。タイトルへ戻ったら**「もう一度、あの日から」ボタンを非表示**にし、次回3月のSCENE10分岐は1周目SCENE11Aへ。
6. 可能なら完了表示で `1周目EDの再テストが可能になりました。新しく開始するか、SCENE10以前から読み込んで確認してください。` と示す。**押下したその場で勝手にシナリオジャンプしない**。

## 絶対に変更しないもの
- `sf.true_end_seen` 相当／既存のTRUEギャラリー開放／MINI＆CORE既読／真BAD記録カード／ゲーム中セーブ／主人公名／全月CLEARフラグ。これらを削除・初期化しない。
- 意図的に**既読真BADのカードが残ったまま、分岐だけ初回へ戻る**。デバッグ目的なので仕様上矛盾しない。
- 複数の「first_ending_seen」等の補助変数を見つけた場合は、その必要性を調査し、`sf.true_bad_seen`だけで分岐が成立する既存／新実装を維持する。新たなTRUE解放条件を増やさない。ユーザーに相談せず既存データを破壊しない。

## 仮コードの意味（現行実装の保存APIを照合してから実際に書く）
```text
onRecordDebugResetClick():
  confirm("1周目ED到達フラグだけを解除します。よろしいですか？")
  if (!approved) return
  sf.true_bad_seen = false
  persistSystemVariablesUsingExistingProjectMechanism()
  refreshDebugStateLabel()
  ensureTitleMenuReadsLiveFlagOnNextRender()
```
**注意**：上記は環境に依存しない疑似コード。`sf`の参照・保存／HTMLボタンへの接続は既存Tyrano実装を読み、正しいAPIに置き換える。全リセット・`localStorage.clear`・全システムセーブ破棄は禁止。

## テストシナリオ
1. `sf.true_bad_seen=false` のとき、初回エンディングへ。DEBUG UIはOFF表示。
2. 真BAD017を表示→flag true → タイトル再挑戦ボタンON。
3. 記録画面を開いてデバッグ解除→確認をキャンセル：ONのまま。
4. 再押下して解除：flag falseが**再起動後も維持**、タイトル再挑戦ボタンOFF。
5. 3月SCENE10以前の安全なセーブから読み込む：再びSCENE11A→暫定EDムービー→真BAD017。
6. 再度真BADでflag true、2周目TRUE経路が復活。ギャラリーと記録が消えていない。
7. 記録画面のタブ・選択・スクロール・戻る操作に問題がない。

**リリース前：** 有効フラグfalseまたはボタン施工の除去を必須項目に。今回は**テスト用に残すことが明示依頼**なので勝手に削除しない。
